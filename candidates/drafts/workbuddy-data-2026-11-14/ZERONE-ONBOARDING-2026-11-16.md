## 客户端兼容性阻塞

用户提供的官方配置在 URL query 中传 `api_key`。v0.2.109 的市场 API Key 配置只绑定 Header，`credentialBindings` 只用于 stdio 环境变量；不能填成 `X-API-Key` 或 Bearer 冒充支持。

需要完成以下任一路径并做真实验收：

- 获得厂商明确支持 Header 的官方证据，并使用同一 Key 验证；当前无此证据。
- 实现 query Key 的安全绑定：公开描述符只保存干净端点、参数名及凭据引用；Key 在本机单独存储，请求发送时注入；检查 Host 动态配置、错误、重定向、重试、诊断、分享、编辑和备份的泄露风险。禁止将带 Key 地址写入公开卡片或提交。
- 官网提及 CLI，但未核实可分发包、版本、许可证或 stdio MCP 能力，不将普通 CLI 自动等同 MCP Server。

仅能匿名握手的连接不得标记为“Key 验证通过”。增加端点时不得静默扩大同一 Key 的发送范围。

## 本机单次验收入口

已准备 [verify-zerone-local.py](verify-zerone-local.py)，可先验证账号业务权限，不依赖尚未完成的市场凭据适配。此脚本不是正式 Connector，也不构成 DSH 端到端验收。

在本机终端用 Python 3 运行脚本，不传 Key 参数；按提示隐藏输入 Key。脚本只向固定 PE 地址发送请求，不跟随重定向。读取工具清单后，最多执行一次已批准的 `get_available_tables({})`，不打印原始响应或错误文本，只统计数据表描述数量并保留响应摘要哈希。

业务请求发送前写入一次性标记 `~/.dsh/acceptance/zerone-pe-20261116-once.claim`；网络失败或响应丢失也不会自动重试，再次运行将拒绝业务调用。不要自行删除标记重试。输出 `~/.dsh/acceptance/zerone-pe-20261116-once.json`，不保存 Key、会话 ID 或数据表内容。业务响应不直接自动标 PASS，须核对脱敏报告；base 仍未授权验收。

验证：`python3 test/zerone-local-acceptance.test.py`，覆盖 Key 特殊字符编码、一次调用/重复运行阻断、未知网络结果不重试、错误与文件无密钥、0600 文件权限、拒绝重定向、SSE 响应 ID 匹配。使用模拟请求，不消耗账号额度。
